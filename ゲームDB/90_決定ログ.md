### ADR-077 2026-08-21: 捨て牌（牌河）を卓心基準の四河にする

- **状況:** 捨て牌が席の端へ押し出され、フェルト中央が空き、牌河の重なりで謎の横スクロールが出ていた。実卓は中央の風盤・宝皿を囲む四河。
- **決定:** 四河を `#center-area.felt-heart` に集める（北6枚行・西東6枚列・南6枚行、手前行は自席側）。`#human-discards` と `.north-discards` / `.west-discards` / `.east-discards` を維持。`98vw` と `overflow-x:auto` を河から外し、卓・フェルトは `overflow-x:hidden`。手牌セレクタと `TILE_*_POS`・グリッド `w s e` は不変。
- **理由:** 実卓と同じく真ん中を基準に並べ、空きと重なりと横スクロールを同時に消す。
- **影響:** `harbin-mahjong.html`（`render()` / `renderDiscardStrip` / 河CSS）、`scripts/verify-hand-layout.mjs`、`scripts/verify-side-hand-parity.mjs`。

### ADR-076 2026-08-20: 左席手牌と自家手牌が角で重ならないようグリッドを組む

- **状況:** 実卓グリッドの南が3列スパン (`s s s`) のため、西の伏せ牌が自家手牌の左端に重なっていた。
- **決定:** 南は中央列だけ (`w s e`)。西東は中段＋南段。縦は `--hand-rack-pad:120px` で13枚を中央列に収める。重なりは `verify-hand-layout` で検出する。`TILE_*_POS` は不変。
- **理由:** 角で牌が欠けると卓として読めない。列を分けて物理的に交差させない。
- **影響:** `harbin-mahjong.html`（`.mj-table .felt-play-column`）、`scripts/verify-hand-layout.mjs`。

### ADR-075 2026-08-20: 対局画面UIを実卓レイアウトから作り直す（ルール・牌座標不変）

- **状況:** 対局UIはアプリHUD／タイトル用漆金の上塗りで、実卓の四方席・門前手牌・中央牌河に見えなかった。
- **決定:** タイトル画面は残し、対局画面だけ `.mj-table` として1から組み直す。配置は手前・左・対面・右、手牌は門前、捨て牌は中央側、鳴きは手牌横。ルール・`TILE_*_POS` / `TILE_HAND_POS`・検証セレクタは不変。木目・フェルト写真は CSS 仮材。本素材は `06_対局卓UI再設計_他AI指示.md`。
- **理由:** ハルビン麻雀は四方卓で遊ぶ。スマホでも「机の上の牌」に寄せないと本体画面が商品に見えない。
- **影響:** `harbin-mahjong.html`（対局 CSS / `render()` の卓HTML）。ロジック関数は不変。

### ADR-074 2026-08-20: 対局卓をタイトル同系の漆・金にし、縦横ドックを足す（牌座標不変）

- **状況:** タイトル・結果ダイアログは漆金に揃ったが、対局中のフェルト・ハブ・席札・河・操作バーは旧デザインのままで、スマホ縦横とも業務HUDに見えた。
- **決定:** 卓枠・フェルト照明・中央ハブ・席札・自家木トレイ・操作ドックをタイトル同系トークンにする。縦は下ドック、横は右下ドック。`TILE_*_POS` / `TILE_HAND_POS`・4席相対位置・牌寸法計算は不変。
- **理由:** 商用2D麻雀（雀魂／格闘倶楽部系）は卓が主役。牌スプライトと検証ビューポートを壊さず材質だけ上げる。
- **影響:** `harbin-mahjong.html`（CSS と `render()` のラベル／action-bar HTML）。ロジック関数は不変。

### ADR-073 2026-08-20: 2Dプレミアム化・Web課金・ストア後続をスコープに入れる

- **状況:** ルールと配牌／和了シネマは強いが、タイトル・HUD・日常モーション・音が業務アプリのままで商用製品に見えなかった。課金・ストアは従来スコープ外。
- **決定:** (1) 単一 HTML の 2D 卓を維持し CSS/Web Animations/Web Audio でプレミアム化する。(2) 無料は CPU やさしい／ふつう＋オンライン。有料ワンタイム「プレミアム」はむずかしい AI・卓テーマ（金縁／夜卓）・和了シネマ差分化。(3) 課金の第一経路は Stripe Checkout（同一 Node サーバ）。App Store は Capacitor 後続で IAP。(4) 牌スプライトとルールは不変。
- **理由:** 売れるかどうかは第一印象と毎日の牌モーションで決まり、エンジン乗り換えより現スタックの演出密度を上げる方が速い。iOS でデジタル商品を売るなら後から IAP が必須。
- **影響:** `harbin-mahjong.html`、`server/online-server.mjs`、`server/shop.mjs`、`audio/`、`legal/`、`manifest.webmanifest`、`native/`、`01`/`02`/`03`/`05`。

### ADR-072 2026-05-29: AI難易度を嵌張ルール向け手牌評価に差し替え

- **状況:** やさしい／ふつう／むずかしいの差がほぼ鳴き確率とランダム打牌だけで、嵌張・扣聴・開門を意識せずポンコツに見えた。
- **決定:** `aiHandUtility`（嵌張待ち・開門・2色・嵌張形）で捨て牌を評価。難易度ごとに `kouTingEnter`・`smartPick`・`defense`・`ronTake` を分岐。扣聴中は `kouTingLegalDiscardIndices` から選択。AIは `kouTingEntryDiscardIndices` で扣聴へ積極移行（難しいほど高確率）。オンラインサーバも同系の評価に更新（ふつう相当固定）。
- **理由:** ルール・牌デザインは変えず、AIだけ哈尔滨麻雀らしくする。
- **影響:** `harbin-mahjong.html`、`server/online-server.mjs`。難易度は `hm_difficulty` に保存。

### ADR-071 2026-05-29: プレイ前ルール確認・扣聴ハイライト・オンライン再接続導線・ルール回帰テスト

- **状況:** 嵌張限定など哈尔滨固有ルールの初見離脱、扣聴中の捨て牌選びの迷い、オンライン切断後の再参加導線不足、ルール変更の回帰検知がレイアウト検証のみだった。

- **理由:** ルール・牌デザインを変えず体験と信頼性だけを上げる（ユーザー方針）。
- **影響:** `harbin-mahjong.html`、`scripts/verify-rules.mjs`、`scripts/verify-helpers.mjs`、`package.json`、`05_バックログ.md`。

### ADR-070 2026-05-29: 左右席の捨て牌は席視点1行→最大2段、鳴き間隔を自家に揃える

- **状況:** 左右席の捨て牌が6枚ごとの縦列でバラバラに見え、鳴き面子同士の間隔も自家・対面より広かった。
- **決定:** 捨て牌は席から見て左端から順に1列（画面上は縦積み）を埋め、5枚超で2列目（2段）に分割。2段時は `strip-side-compact` で牌をやや縮小。鳴きは `melds-row` gap 1px・面子内 margin 詰めで自家 `meld-group` 相当に。
- **理由:** 左右席も自家と同じ「河の流れ」で読めるようにし、鳴きの視認性を統一する。
- **影響:** `harbin-mahjong.html`（`renderSideDiscardRiver`、`.side-discards-zone` CSS）。

### ADR-069 2026-05-29: 山切れ宝引き和了は「待ち＝宝牌」のときだけ宝中宝得点

- **状況:** 山0・扣聴者が宝を引いて和了したら、待ちに宝牌がなくても一律 `treasure:true`（+36）になっていた（例: 宝2筒をポン済みで待ちは別牌なのに南が宝中宝）。
- **決定:** 宝中宝得点は **嵌張待ちに宝牌が含まれる** ときのみ。山切れ宝引きは `playerWaitsForTreasure` / `kouTingWaitsForTreasureTile`（和了牌を除いた手牌の待ち）で判定。和了可だが待ち≠宝 → **通常ツモ**（+12）。和了不可 → 流局。
- **理由:** 宝中宝は「扣聴の待ちが宝牌と一致」する特殊和了であり、宝牌を引いただけでは足りない。
- **影響:** `harbin-mahjong.html`（`resolveKouTingTreasureDraw`）、`server/online-server.mjs`（`finishTreasureDrawWin`）。

### ADR-068 2026-05-29: 扣聴は開門（チー・ポン・大明槓）後のみ

- **状況:** 鳴きなしの対面が扣聴・宝中宝和了していた。実装は `checkWin` で `kouTing` を開門の代替にしており、`shouldEnterKouTing` も鳴き不要だった（ADR-043「開門不要」と矛盾するユーザールール）。
- **決定:** 扣聴に入る・和了するには **`melds.length>0` 必須**。`shouldEnterKouTing`・`kouTingEntryDiscardIndices`・サーバ同関数・`canWin` を統一。誤って `kouTing` だけ立っている席は `updateAllTenpai` で解除。
- **理由:** 「チー・ポンもしていないのに扣聴できない」という哈尔滨ルールの正しい解釈。
- **影響:** `harbin-mahjong.html`、`server/online-server.mjs`、`04_ルール仕様_コード対応.md`、ルール説明 `rule2`。

### ADR-067 2026-05-29: 宝中宝ボタンは扣聴中の「捨て終わり」（手牌＝exp）後のみ

- **状況:** 摸牌直後の自動扣聴で待ち＝宝牌のとき、まだ1枚捨てる前に「宝を見る」が出ていた。
- **決定:** `canOfferKouTingTreasureNow`（手牌枚数＝`expectedHandCount`）を満たすまで宝中宝 UI を出さない。捨て牌・claim 終了後の `finalizeAfterDiscardCycle` / `finishNoClaim` で初めて `maybeBegin*` を呼ぶ。
- **理由:** 「先に牌を捨ててから宝確認」のユーザー要望。
- **影響:** `harbin-mahjong.html`、`server/online-server.mjs`。

### ADR-066 2026-05-29: 宝中宝（待ち＝宝）は即和了せず「宝を見る」→「宝中宝！」の手動フロー

- **状況:** 扣聴成立直後に待ちが宝牌と一致すると、人間プレイヤーでも自動で宝中宝和了→結果表示となり、捨て牌後のユーザー操作（宝確認・演出）がなかった。
- **決定:** 人間は **即 `resolveWin` しない**。(1) 不要牌を捨てて扣聴成立（他席のロン応答は従来どおり claim 経由）。(2) 「**宝を見る**」で宝牌を表向き表示。(3) 「**宝中宝！**」で `playHumanWinCinema` 付き和了。AI は従来どおり即和了。オンラインは `reveal_treasure` / `treasure_win` アクションを追加。
- **理由:** ユーザー要望「最後の判定は捨てた後、自分発信で宝確認→ド派手演出で和了」に合わせる。
- **影響:** `harbin-mahjong.html`（`kouTingTreasurePending`・`humanRevealKouTingTreasure`・`humanClaimKouTingTreasure`・`finalizeAfterDiscardCycle`）、`server/online-server.mjs`。

### ADR-065 2026-05-29: 牌の下駄色を CSS 変数で統一（伏せ牌を濃く／左右捨て鳴きを自家手牌と同系に）

- **状況:** 自家手牌（デザイン2＋CSS 上端の青下駄）と、左右の鳴き・捨て牌（PNG 内蔵の青縁）、伏せ牌（`.tile.back` の明るいグラデ）で下駄の色味が揃っていなかった。
- **決定:** PNG アセットは触らず、**CSS 変数 `--tile-geta-*` / `--tile-back-*`** で下駄色を一本化。(1) 伏せ牌（`.tile.back`・東西 `hand-face.opp-hand` 裏）をやや濃い青に。(2) 左右の表向き `hand-face.opp-hand` は自家と同様に `::before` 下駄＋`.tile-art` を上15%でクリップし PNG の青縁を隠す。
- **理由:** 画像編集・再ビルドより CSS の方が作業が軽く、ADR-061 のデザイン割当を維持したまま視覚的整合を取れる。
- **影響:** `harbin-mahjong.html`（`.table-felt` 変数、`.tile.back`、左右捨て鳴き・手牌列の hand-face ルール）。

### ADR-064 2026-05-29: 扣聴成立直後の「宝中宝」（待ち＝宝牌で即和了）

- **状況:** 扣聴に入った瞬間に宝牌が表向きになり、待ち牌が宝牌と一致する局面（例: 待ち3索・宝3索）でも「牌を引く」表示のまま和了しなかった。従来の宝中宝は山切れ後の宝引きのみ。
- **決定:** 扣聴成立直後（捨て牌で入る／摸牌後の自動扣聴のいずれも）、`getKatanWaits` の待ちに `G.treasure` が含まれれば **山引きなしで即和了**。名称 **宝中宝**（`treasure: true` / `isTreasure`）。得点はツモ12点相当を3倍し、和了者 **+36**、他家各 **−12**（`getTreasureScoreDeltas(seat, 12)`）。オフラインは `tryResolveKouTingTreasureWin`、オンラインは `tryFinishKouTingTreasureWin` → `finishHand({ treasure: true })`。
- **理由:** 哈尔滨ルールの「扣聴で宝が待ちと一致したら即アガリ」を実装。ユーザー報告の未実装ギャップを解消。
- **影響:** `harbin-mahjong.html`（`enterKouTingByDiscard`・`updateAllTenpai`・`resolveWin`・オンライン `buildOnlineGame` 演出）、`server/online-server.mjs`（`kouting`・`maybeAutoEnterKouTing`・`applyWinScores`）、`ゲームDB/04_ルール仕様_コード対応.md`。

### ADR-063 2026-05-29: 手牌スプライトURLを `hand-tiles.png` に固定（Vercel白牌対策）

- **状況:** Vercel 本番で自家・左右の `hand-face` 牌が白抜け。`TILE_HAND_SHEET_URL` がソース内の NFD 文字列 `名称未設定のデザイン (2).png` を参照しており、Git/Vercel 上の NFC ファイル名と一致せず 404。ビルドは `hand-tiles.png` を配布済みだった。
- **決定:** 実行時参照は **`hand-tiles.png`（ASCII）のみ**。`preloadTileTextures` も同様。`verify-deploy-assets` は日本語ファイル名を必須から外す（ローカル開発用ソース `名称未設定のデザイン (2).png` はビルド入力として残してよい）。
- **理由:** 本番 CDN で Unicode 正規化差による 404 を防ぎ、ADR-049 の配布名と一致させる。
- **影響:** `harbin-mahjong.html`、`scripts/verify-deploy-assets.mjs`。

### ADR-062 2026-05-29: 配牌の自家・対面を1列着地に／対面の白牌バグ修正／ロンを任意選択＋ド派手演出

- **状況:** (1) 配牌演出で自家・対面が「二段三列」グリッドのままで、`runReveal` の collapse 演出はスキップ時に発火せず実質見えていなかった。(2) 対面（北）の手牌が白く表示される（ADR-060 で足した `#top-area .tile.lg.hand-face:not(.opp-hand){background:#fff}` が裏牌 `.tile.back.lg.hand-face` に当たっていた。ADR-061 で当該 CSS と `HUMAN_RIVER_TILE_CLS` は撤去済みのため現コードでは青背に復帰）。(3) ロンが扣聴時は自動和了で、ユーザーに選択権がなかった。和了演出も控えめだった。
- **決定:** (1) `#human-hand.deal-staging` と `.north-hand-row.deal-staging` を縦列→横1列に変更し、配牌中の自家・対面の手牌を横1列で描画（飛来した牌がそのまま横一列に着地）。左右席は従来どおり縦1列。collapse 用関数は無害な no-op として残置。(2) 対面白牌は ADR-061 の撤去で解消済み（再発防止として確認）。(3) `afterDiscard` の扣聴自動ロンを廃止し、常に `humanOptions.push('win')`＝「ロン！/スキップ」ボタンで任意選択に。自家がロン/ツモ/宝中宝を選んだ瞬間に全画面の `#ron-cinema`（巨大漢字スラム＋放射光＋衝撃波＋紙吹雪＋画面シェイク＋効果音）を再生し、終了後に結果オーバーレイへ。
- **理由:** 「配牌の自家・対面を1列に」「対面が白い理由の解消」「ロンを任意選択にしてド派手演出」というユーザー要望に対応。
- **影響:** `harbin-mahjong.html`（deal-staging CSS、`renderSeatHand`/`humanTiles` の配牌1列化、`afterDiscard` のロン任意化、`#ron-cinema` の HTML/CSS/`playHumanWinCinema`、`resolveWin` のフック）。ルール仕様の変更なし。検証: `verify-hand-layout.mjs` pass。

### ADR-061 2026-05-29: 牌デザインの割当を確定（自家手牌=デザイン2/自家・対面の鳴き捨て=7198/左右=デザイン2）＋左右の鳴き捨て回転を反転

- **状況:** ADR-060 で「捨て・鳴きの色を手牌に合わせる」を取り違え、自家・対面の鳴き/捨てまで `名称未設定のデザイン (2)` に変えてしまった。ユーザーの正しい意図は逆向きの統一だった。加えて左右席の捨て/鳴きの牌の回転（天地＝青い厚みの向き）が反転していた。
- **決定:** 牌デザインの割当を次に確定する。**自家手牌＝`名称未設定のデザイン (2)`（青い上端）**／**自家の鳴き・捨て＝`7198`**／**対面（北）＝`7198`**／**左右席の手牌・鳴き・捨て＝すべて`名称未設定のデザイン (2)`**。実装は `HUMAN_RIVER_TILE_CLS` を `'lg'`（7198）へ戻し、ADR-060 で足した自家/対面 hand-face 用 CSS を撤去。左右の鳴き/捨ては `opp-rot` を反転（左: right→left、右: left→right）して青い厚みが中央側を向くようにした。鳴きの位置は左=手牌列の上／右=下のまま（ユーザー確認済み）。
- **理由:** ユーザー指定「自家手牌はデザイン2／自家・対面の鳴き捨ては7198／左右は全部デザイン2」「左右の捨て鳴りの向きが逆」を正しく満たすため。
- **影響:** `harbin-mahjong.html`（`HUMAN_RIVER_TILE_CLS`、自家/対面 hand-face CSS の撤去、`renderDiscardStrip`・`renderSideMeldGroups` の左右 `opp-rot` 反転）。`scripts/verify-side-hand-parity.mjs` の回転期待値を反転に追随。検証: `verify-hand-layout.mjs` pass、`verify-side-hand-parity.mjs` 全ビューポート 100。

### ADR-060 2026-05-29: 卓上全牌をデザイン牌へ統一し、左右の捨て密着・鳴きを「手牌の左」に縦積み

- **影響:** `harbin-mahjong.html`（`renderFeltWallOrnaments`・CSS・`renderDiscardStrip`・`render()`）。

### ADR-014 2026-05-15: 配牌山28枚/辺と手前牌の視点（縦反転）

- **状況:** 四方山は112枚（辺あたり28枚＝14列×2段）だが、配牌演出は各辺2×7枚で枚数感と違った。手前手牌は真上視点なのに立体・青帯が下辺に残り、図柄だけ正立のまま「牌全体を180°入れ替え」したい要望があった。
- **決定:** 配牌演出の山DOMは **各辺2段×14枚（計112）** にし、各セルを裏色＋側面の二色で積みの示唆に寄せる。手前の **表牌** は `#bottom-area #human-hand .tile` に **`scaleY(-1)`**、**図柄は `.tile-art-img`／`.tile-svg` にのみ `scaleY(-1)`**（`.tile-art` 全体にかけるとスプライトの下縁まで元に戻る）。**`::before` は手前表牌では `display:none`**（反転後にスプライトの青縁と二重になるため）。下面に回り込んだ `::after` 光沢は非表示、扣聴枠は `::after` を上書きで維持。手前だけ白面グラデと影を参照画像寄せに調整。摸牌・ホバー・配牌めくりは `dealHandFlipHandFace` 等で合成。
- **理由:** 疑似要素の付け替えだけでは既定の `box-shadow` 由来の下辺の青が残るため、幾何として縦反転が確実。他家は従来のまま。
- **影響:** `harbin-mahjong.html`（`buildDealSquareWall` の `perTier`、`.deal-wall-tile`、`#bottom-area #human-hand` の表牌 transform／`::before` 非表示／`::after`、配牌 keyframes）。

### ADR-013 2026-05-15: オンライン扣聴・宝牌・山切れ・10局の仕様確定

- **状況:** ADR-012 でオンライン扣聴の基盤を実装したが、クライアント同期の詳細（宝牌の公開制御・山切れ分岐・10局セット）が明文化されていなかった。
- **決定:** サーバは `publicState` に `kouTing` を含め配信。扣聴手番は `legalActions:['draw']` → `kouTingLegalDiscards` 返却 → discard → replenishなし → `nextTurn` の順で進める。宝牌は他家へ `{hidden:true}` で送信し、自家は扣聴中・使用済・山切れ時に表示。山切れは `wallExhausted` イベントで扣聴者のみ宝引き・他は流局。オンライン10局上限は **要ディレクター判断**（未決定）。
- **理由:** Cursor/Codex が実装・QA できる受け入れ条件に落とすため仕様を明文化した。
- **影響:** `server/online-server.mjs`（`publicState`・`legalActions`・`wallExhausted`）、`harbin-mahjong.html`（`treasureFaceKnown`・オンライン受信ハンドラ）、`ゲームDB/04_ルール仕様_コード対応.md`（オンライン同期仕様節追加）。

### ADR-012 2026-05-15: オンライン出荷ブロッカー修正

### ADR-007 2026-05-14: 親決めルーレットと連荘・親流れ

### ADR-006 2026-05-13: 10局セット・親ダイス・捨て牌配置・終局開示・AI得点

- **状況:** 局ごとに得点がリセットされ、常に自分が親。捨て牌は中央スクロール。終局で他家手牌非公開。AIが和了しない。  
- **決定:** オフラインは **10局セット**で合計点を保持し **次の局** で継続。各局開始前に **2d6で親決め** 演出。捨て牌は **各席付近** に固定表示。終局は **四家手牌開示**。AIは鳴き・ツモ和了判定を強化し難易度差を付与。  
- **理由:** テストプレイで挙がった対戦ゲームとしての体裁と得点競争を満たすため。  
- **影響:** `harbin-mahjong.html`、`ゲームDB/90_決定ログ.md`。

### ADR-005 2026-05-13: テンパイ表示を廃し、宝牌は扣聴中のみ公開。扣聴は先摸後切

- **状況:** 嵌張待ちだけで「テンパイ」表示・宝牌公開され、ヤオ九なしでも宝が見えた。扣聴の成立もテスト用の 8萬/9萬 縛りが残っていた。  
- **決定:** プレイヤー向け「テンパイ」概念は使わない。宝牌は **自分が扣聴中** または **使用済** のときだけ表向き。扣聴移行は摸牌後に **和了条件（嵌張・ヤオ九・2色・刻順・開門 or 扣聴）** を満たす待ちのときのみ。通常手番は **先切後摸**、扣聴手番は **先摸後切**（捨て後の本引きはしない）。  
- **理由:** 実地のハルビン麻雀の理解と UI の齟齬を解消するため。  
- **影響:** `harbin-mahjong.html`、`ゲームDB/04`、`server/online-server.mjs`（宝公開・扣聴更新の整合）。

### ADR-003 2026-05-11: 扣聴を先出後引きに揃え、鳴き後に捨て主が摸牌する
