### ADR-048 2026-05-21: 配牌直後の流局（山0）修正

- **状況:** オフラインで配牌直後に山が0枚になり流局になる。
- **決定:** `startRound` で `dealHarbinHands` 返却の `wall`（入力と同一配列）を `wall.length=0` してから `push` していた処理を削除。`dealHarbinHands` は牌山を破壊的に更新するだけとする。
- **理由:** 同一参照を空にしたため残り牌がすべて消えていた。
- **影響:** `harbin-mahjong.html`。

### ADR-047 2026-05-21: 配牌前ダイス（開門者・取り始め）と牌山周回

- **状況:** 配牌演出が対面の山だけ減るなど、正式な開門ダイス手順が未実装だった。
- **決定:** 親2d6で開門者（(合計-1)%4 で席順）、開門者2d6で牌山左から空ける墩数（合計→列）。牌壁は開門側から反時計回りに6枚塊を消費。`#deal-dice` で振る演出（ボタン・音・アニメ）。オンラインはサーバが `dealBreak` を保持。
- **理由:** 哈爾浜麻雀の正式手順とユーザー要望に合わせる。
- **影響:** `scripts/harbin-deal.mjs`、`harbin-mahjong.html`、`server/online-server.mjs`、`04_ルール仕様_コード対応.md`。

### ADR-046 2026-05-21: ハルビン配牌ロジックと6枚塊演出

- **状況:** 配牌が従来の13+1方式のまま。演出も1枚ずつ増え、6枚塊×2巡に見えない。
- **決定:** `scripts/harbin-deal.mjs` に親→反時計回り・6枚×2巡・チョンチョン(1+跳2+1)・閑家+1を実装。クライアント `startRound` とサーバ `beginNewHand` で使用。演出は1ステップで6枚同時着牌（二段三列グリッド）。
- **理由:** ハルビン麻雀の実際の取り方とユーザー要件に合わせる。
- **影響:** `scripts/harbin-deal.mjs`、`harbin-mahjong.html`、`server/online-server.mjs`、`04_ルール仕様_コード対応.md`。

### ADR-045 2026-05-21: ルーレット後にメニューへ戻る不具合

### ADR-044 2026-05-21: 親決めルーレット表示と配牌演出（6枚×2巡・チョンチョン）

- **状況:** ルーレットの当たりが常に「東」に見える（当選席の門風を盤面に描いていたため）。配牌演出は4枚×3巡+1枚ずつで、ハルビン式の6枚塊×2巡・親跳張・閑家補牌と不一致。
- **決定:** ルーレットは **手前/左/対面/右** の固定ラベルで回し、当選後に「○○が親（東）」と表示。配牌演出は **6枚×2巡 → 親1・跳2・1 → 閑家各1**。手牌は配牌中 **3列×2行** で見せる。
- **理由:** 門風は親決定後に付く。配牌の見え方を実際の取り方に近づける。
- **影響:** `harbin-mahjong.html`、`04_ルール仕様_コード対応.md`。

### ADR-043 2026-05-21: オンライン親初打・切断・扣聴入口の整合

- **状況:** 探索で、オンライン親の初打後に本引きが走る、SSE 切断後に卓が更新停止、切断席で手番が止まる、サーバのみ開門必須で扣聴入口が欠ける、オンラインで未実装の暗槓 UI が表示される、が判明。
- **決定:** サーバに `dealerOpeningDiscardNoDraw` を追加（オフライン同様）。`isHumanSeat` は `connected !== false` の席のみ人間扱い。SSE `onerror` は卓を維持し再接続バナー＋ `reconnectOnlineSse()`。扣聴入口はクライアントと同じ条件（開門不要）。暗槓/加槓ボタンはオンラインでは非表示（サーバ未対応は ADR-042 のまま）。宝牌は山切れ時も表向き。
- **理由:** 手牌枚数・対局継続・ルール一致・誤操作防止のため。
- **影響:** `server/online-server.mjs`、`harbin-mahjong.html`。同一席の `playerId` 再参加（BL-002）は未実装。

### ADR-042 2026-05-21: 自家ツモカンの先出後引き分岐（A/B）

- **状況:** 暗槓後に常に「捨て待ち」となり、先出後引きの2パターン（摸牌後カン＝ターン終了、ターン開始カン＝嶺上→捨て→本引き）が未実装だった。
- **決定:** **分岐A**（捨て→本引き→4枚目でカン）: 嶺上補充後ターン終了（嶺上開花可）。**分岐B**（ターン開始・捨て前に暗槓/加槓）: 嶺上→捨て→本引き→次家。大明槓（他家捨て）は従来どおり捨て1枚のみ。
- **理由:** ユーザー指定のハルビン麻雀カン手順に合わせるため。
- **影響:** `harbin-mahjong.html`（`executeSelfKan`・`finalizeAfterDiscardCycle`・UI ボタン）。オンラインサーバは未対応。

### ADR-041 2026-05-17: 自家鳴きを捨て牌デザインに・捨て牌ゾーン拡幅・スクロール廃止

### ADR-040 2026-05-17: ロン時の点炮表示と哈尔滨式得点（听牌放炮／未听包两家）

- **状況:** ロン和了後に誰の捨て牌か判別しづらい。得点がロンでも三家均等−2点のみで、波克ルールの「未听牌放炮は包两家」とずれていた。
- **決定:** 放銃牌に `ron-fired` ハイライト＋卓上ビーム演出＋中央バナー。得点は嵌張ベース2点: **ツモ**は各家−4（計+12）、**听牌放炮**は放銃含め三家各−2、**未听牌放炮（出冲）**は放銃者のみ−6・他家0。听牌判定は打牌時点の `kouTing` または `getKatanWaits(hand)`。
- **理由:** 波克哈尔滨麻将の結算要約（`90` 参照元: 百度经验）に合わせつつ、現行の簡易点制度を維持するため。
- **影響:** `harbin-mahjong.html`（`resolveWin`・`renderDiscardStrip`・`playRonRevealFx`）、`server/online-server.mjs`（`applyWinScores`・`lastDiscardMeta`）。

### ADR-038 2026-05-17: チー直後など「捨てて扣聴」入りを UI とオンラインで許可

- **状況:** チー直後は手牌が `expected+1` 枚になり、捨て1枚で扣聴形に入れる局面があるが、摸牌後の自動扣聴だけが動き「扣聴」ボタンもなく、タイマーが通常捨てしてしまった。
- **決定:** `kouTingEntryDiscardIndices` で入聴可能な捨て候補を列挙。人間 UI に「扣聴」→ 候補牌のみ捨てて `kouTing=true`。オンラインは `legalActions` の `kouting` に `indices` を載せ、`kouting` アクションで捨て＋入聴。タイムアウトは候補が1枚だけならその捨てで入聴。
- **理由:** 鳴き直後の `exp+1` 枚は `getKatanWaits` 対象外のため、摸牌後ロジックだけでは入聴できないため。
- **影響:** `harbin-mahjong.html`、`server/online-server.mjs`。

### ADR-025 2026-05-15: 手札の牌間白線をやめ鳴き牌寄りの立体感に

- **状況:** 手札の牌と牌の間にスプライト余白の白い縦線が見えダサい。鳴き牌のような立体感は許容。

### ADR-024 2026-05-15: 手札上から視点の縦窓を詰めて青帯上の白灰帯を除去

- **状況:** 手札が下から見ると「灰→青→白→灰」と上行の隙や余白が重なって見える。
- **決定:** `tileFaceArtHand` で `--ty` に **+16px** のオフセット（`HAND_SPRITE_TY_INSET`）を加え、CSS の縦除数を **161→156** にして可視高をやや狭める。
- **理由:** スプライト行間や上行下端が縦窓に入り込まないようにし、牌面は「側面の灰〜青」のみに見せるため。
- **影響:** `harbin-mahjong.html`。
- **追記（同日）:** 二重 `scaleY(-1)` によりスプライト上の白隙間が画面下に来るため、`TILE_HAND_POS` の **ty を青帯上端**（萬234・索418・筒596・中46）に変更。`HAND_SPRITE_TY_INSET` と `clip-path` は廃止。縦除数 **150**。
- **追記2:** `hand-face` は **反転をやめ** `background-position`（px）で切り出し。牌箱の白グラデを外し **aspect-ratio 116/158** で下端切れを防止。青の上の白灰は含めない。

- **決定:** Obsidian 上の **`ゲームDB/` を「ディレクター DB」** とし、目的・アーキ・フロー・ルール・バックログ・決定をここに集約。AI には `00_ゲームDBインデックス` の読順を渡す。  
- **理由:** 同じ用語・同じ優先度で複数モデルが動けるようにするため。  
- **影響:** `これまでのまとめ`・`オブシディアン取扱説明`・`ようこそ` から本フォルダへリンク。
