# ルール仕様（コード対応）

**原則:** プレイヤー向けの「正」は **実装** である。仕様書とコードが食い違ったら、**ディレクターがどちらを正にするか決めて**本ノートと `90_決定ログ` を更新する。

## 牌の構成

- 萬子・筒子・索子 1〜9 各 4 枚＋**中**（`z` suit, `num:5`）4 枚、計 **112 枚** デッキ。風牌・白・發は使用しない（`createDeck` / `server/online-server.mjs` と整合）。

## 親（セット対局）

- **第1局:** ルーレット演出で **親席（real seat 0〜3）** をランダム決定（`spinDealerRoulette`）。ルーレットの文字は **卓上の位置（手前・左・対面・右）** であり、当たった席が親になる。**親になった席だけが東風**（門風）。他席は半時計回りに南・西・北（`windLabelForRealSeat(real, dealerReal)`）。オンラインはサーバーが親席を決め、クライアントは同席で演出。  
- **第2局以降:** 前局の結果に応じて `advanceMatchDealer`（オフライン）／サーバー `startNextHand`（オンライン）。**流局**または**親の和了**は連荘（同席）。それ以外は `nextPlayer`（半時計回り）で親交代。  
- **席風表示:** 親席を東風とし、半時計回りに南・西・北を割り当てる（`windLabelForRealSeat`）。オフラインもオンライン同様、**自分は常に view 0（手前）**、他家は `offlineViewSeat` / `onlineViewSeat` で回す。

## 配牌（112枚・宝除き山から）

**ロジックの正:** `scripts/harbin-deal.mjs` の `dealHarbinHands`（`startRound` / `beginNewHand` から呼ぶ）。

### ダイス（開門）

1. **親が2d6:** 合計で開門者を決定（1,5,9=親 / 2,6,10=下家 / 3,7,11=対面 / 4,8,12=上家）— `openerSeatFromDealerDice`。  
2. **開門者が2d6:** 合計で正面牌山の左から空ける墩数を決め、その次の列から取り始める — `breakColumnFromDice`。  
3. 配牌は開門位置の牌壁から **反時計回りに牌山を回る**（`wallSidesFromOpenerView` / `DEAL_WALL_STATE`）。

### 取り配り

1. 開門者から反時計回りに **6枚塊×2巡**（各12枚）。  
2. **親チョンチョン:** 1枚 → 跳2枚 → 1枚（親14枚）。  
3. **閑家補牌:** 各1枚（13枚）。  
4. `validateHarbinHands` で枚数検証。

**演出:** `#deal-dice` で親→開門者のダイス（人間席はボタン＋音）。`buildDealCinemaSteps` で6枚塊を一括着牌。

## 手番の流れ（先切後摸 / 扣聴は先摸後切）

- **通常:** 捨て → 鳴き応答が終わったら捨て主が山から本引き（`finalizeAfterDiscardCycle` → `drawAfterDiscard`）→ 次家の番。親の最初の1打だけ本引きなし（`dealerOpeningDiscardNoDraw`）。  
- **扣聴中:** 自分の番は **先に山から1枚**（`humanDraw` / `kouTingDrawThenAutoDiscard`）→ **聴牌を保てる牌だけ捨て**（`kouTingLegalDiscardIndices`）。捨てたあと **本引きしない**（`finalizeAfterDiscardCycle` で `nextTurn` のみ）。  
- **扣聴への移行:** 通常の本引きの直後、摸った牌を除いた手牌が **嵌張待ちのみ** かつ **和了条件（`checkWin` と同じ：開門 or 扣聴・ヤオ九・2色以上・刻子＋順子）** を満たすときだけ `kouTing=true`。13枚時点の自動扣聴はしない。  
- **宝牌:** 山の最後の1枚。プレイヤー UI では **自分が扣聴中** または **使用済** のときだけ表向き（`treasureFaceKnown`）。山切れ時の宝引きは **扣聴中のプレイヤーのみ**（非扣聴は流局）。

## 和了制限: カタン（嵌張）限定

クライアント `harbin-mahjong.html` 内のロジック概要:

- **待ちの型**は `waitTypesForWin` で分解（対子・順子・刻子）に応じて `tanki`（単騎）、`shanpon`（両面待ちの一部としての双碰扱い）、順子内なら中央待ち `katan`（嵌張）・辺 `side` などに分類。  
- **`isPureKatanWin`**: 待ち型の集合が **ちょうど `katan` のみ 1 種** のとき真。  
- **`getKatanWaits`**: 通常の待ち候補のうち **純粋嵌張和了のみ** に絞る。コメント上、単騎・双碰・辺張・両面が混ざる待ちは **不可**（`katan.length !== waits.length` なら待ちなし扱い）。

ディレクター向け一言: **「嵌張だけが待ちになる形以外はアガれない」** 方向の強い縛り。ルール説明 UI は `rule1` 文字列と実挙動を必ず揃える。

## 先出後引き・扣聴・鳴き後の摸牌（クライアント）

- 手番の流れは上記「手番の流れ」が正。`drawAfterDiscard` / `replenishDiscardAfterCall` / `humanDraw` / `kouTingDrawThenAutoDiscard` / `kouTingLegalDiscardIndices` / `finalizeAfterDiscardCycle` が実装の入口。  
- **大明槓:** 手3＋他家捨て1で `minkan`（`type:'kan'` の4枚）。ポンと併存し UI では両方選択可。鳴き後は捨て1枚のみ（本引きなし）。
- **自家暗槓・加槓（ポン＋手牌1）:** `executeSelfKan`。**分岐A**（先に捨て→本引きで4枚目）: 嶺上補充（`wall.pop`）後ターン終了、追加の捨てなし（嶺上開花可）。**分岐B**（ターン開始・捨て前）: 嶺上→捨て→本引き→次家。ADR-042。

## オンライン同期仕様（扣聴・宝牌・山切れ）

### 扣聴の同期

- `room.state.players[i].kouTing: boolean` をサーバが保持し、全クライアントへブロードキャスト（`publicState`）。
- 扣聴中プレイヤーの手番: サーバの `legalActions` は `['draw']` のみ返す。クライアントは `draw` を送信。
- サーバは `draw` 受信後に手牌へ摸牌し、合法捨て牌インデックス `kouTingLegalDiscards: number[]` を当該クライアントへ返す。
- クライアントは `kouTingLegalDiscards` に含まれる牌だけ選択可にして `discard` を送信。
- サーバは `discard` 受信後、本引き（replenish）なしで `nextTurn` を呼ぶ。

### 宝牌の公開制御

- サーバは宝牌（山最後の1枚）を `{hidden:true}` として他プレイヤーへ送信（id 非公開）。
- 自プレイヤーには宝牌の完全情報（id・suit・num）を届ける。
- クライアントは `self.kouTing === true` または `G.treasureUsed === true` または `G.wall.length === 0` のとき宝牌を表向き描画（`treasureFaceKnown`）。

### 山切れ時の処理

- 山が0枚になったらサーバが `wallExhausted` イベントを全クライアントへ送信。
- 扣聴中のプレイヤーは宝引きオプションを受け取り、当たれば和了。
- 非扣聴プレイヤーは流局扱い（ADR-007の親交代ルールを適用）。
- その後 `startNextHand` で次局を開始。

### 10局セット（オンライン）

> **要ディレクター判断:**
> - オンラインでも10局固定上限にするか、ルームが続く限り無制限にするか未決定。
> - 10局終了後に同じルームで再スタートするか、新ルームを作るかも未定。
> - 接続断プレイヤーが発生した場合の局進行（AI代打・一時停止・強制流局）の扱いも未定。
